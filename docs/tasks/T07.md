# T07 — Security và log tối thiểu

Ngày: 2026-10-19 · Owner: C · Status: **DONE**

## Mục tiêu (spec mục 20.3)
JWT validation từng service, internal API credential (`X-Internal-Token`), JSON errors thống nhất, correlation filter/log structured; health access hợp lý. **Chưa code nghiệp vụ để "thử luôn".**

Acceptance theo spec: token sai/expired bị 401; role sai bị 403; internal API thiếu credential bị chặn bằng probe test; correlation giữ qua HTTP test.

## Dependency đã kiểm tra
- **T06 DONE** — identity-service: pattern JWT RS256 issue/verify đã được regression tests kiểm chứng sau F01 (temporal claims, skew 0s, iss/aud/sub/role); `JwtService.loadPublicKey` public static để tái sử dụng; error JSON {code,message,correlationId,details} theo contract §1.1 (bằng chứng: docs/tasks/T06.md + fix-followup-2026-10-19.md).
- **T05 DONE** — contract chốt: `api-contracts.md` §2 JWT claims/verify rules, §5 correlation ID, §7 quyết định #8 internal token; matching/payment không có REST API surface (§3/§4) → chỉ hạ tầng tối thiểu.

## Quyết định chính (lượt này)
1. **Chiến lược probe-test**: driver/trip/matching/payment chưa có controller nghiệp vụ (T09+), nên security được enforce ở tầng filter trước dispatch — probe test gọi các path contract (`/api/drivers/me/profile`, `/internal/reservations/{id}`, `/api/trips/quote`...) và assert 401/403 từ filter; token hợp lệ + path chưa có controller → 404 JSON qua `GlobalExceptionHandler`. Không thêm endpoint mới, không sửa contract.
2. **Quy tắc role theo service (tầng filter)**: driver-service — mọi `/api/drivers/**` yêu cầu DRIVER. trip-service — POST `/api/trips/quote`, POST `/api/trips` yêu cầu PASSENGER; POST `/api/trips/{id}/accept|reject|start|complete` yêu cầu DRIVER (regex); các path khác chấp nhận role đã xác thực bất kỳ. matching/payment — **không có security filter**: contract §3/§4 không cho họ API surface; chỉ `CorrelationIdFilter` + `GlobalExceptionHandler`.
3. **Class security nhỏ nhân bản theo service** thay vì module chung (spec yêu cầu 5 module độc lập): `Role`, `AuthenticatedUser`, `UnauthorizedException`, `ForbiddenException`, `JwtVerifier`, `CorrelationIdFilter`, `ApiSecurityFilter` (chỉ driver/trip), `ApiError`, `GlobalExceptionHandler`.
4. **identity-service**: thêm `CorrelationIdFilter` mới (@Order(1)) và đổi `JwtAuthFilter.correlationId()` sang delegate về nó — identity khớp contract §5 (UUID hợp lệ hoặc server-generated; trước đó chấp nhận mọi chuỗi không trống). 16 tests hiện có không bị ảnh hưởng.

## Acceptance đạt (spec §20.3)
| Tiêu chí | Bằng chứng |
|---|---|
| Token sai/expired → 401 | probe driver+trip: expired (`exp = now-60`, skew 0s), tampered signature (lật bit byte đầu chữ ký), aud không chứa service này, thiếu token — tất cả 401 `UNAUTHORIZED` |
| Role sai → 403 | PASSENGER trên `/api/drivers/me/profile` → 403; PASSENGER trên trip accept → 403; DRIVER trên quote → 403 (`FORBIDDEN`) |
| Internal credential thiếu bị chặn bằng probe test | PUT `/internal/reservations/{id}` không có / sai `X-Internal-Token` → 401 `INVALID_INTERNAL_CREDENTIAL`; token đúng qua filter (→ 404 JSON vì chưa có controller — T10) |
| Correlation giữ qua HTTP test | UUID hợp lệ được echo trong error body; header thiếu/sai → server-generated UUID hợp lệ; MDC set/clear mỗi request, log INFO `method/path/status/correlationId` |
| Health access hợp lý | `/actuator/health` 200 UP không cần auth ở cả các service (probe/smoke tests) |

## Giới hạn / ghi chú
- Chưa có business handler (T09+): probe 404 là hành vi mong đợi, không phải lỗi.
- matching/payment không có API surface theo contract §3/§4 — chỉ hạ tầng correlation + JSON error; khi internal endpoint xuất hiện ở các task sau sẽ thêm security filter tương ứng.
- Chạy local driver-service/trip-service cần env tiến trình: `JWT_PUBLIC_KEY_PATH` (cả hai) và `INTERNAL_API_TOKEN` (driver) — không nằm trong Compose `.env`.
