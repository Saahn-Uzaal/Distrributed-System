# T14 — Consumer inbox và retry (matching-service)

Owner: B · Dependency: T04 (DONE), T05 (DONE), T07 (DONE) · Spec §20.4, events.md §2/§4/§6

## Mục tiêu

matching-service consume `TripRequested` từ queue `matching.inbox`: validate envelope theo events.md §2; dedup bằng unique `(consumer_name, event_id)` commit trong transaction cùng handler — ACK chỉ sau commit (rollback → không ACK → redelivery); transient failure retry in-process có giới hạn rồi `reject(requeue=false)` vào DLQ; malformed/unsupported republish chủ động vào `ride.events.dlx` kèm header `x-dlq-reason`. Handler là probe theo spec §20.4 ("dùng handler probe test trước khi có matching thật"), thay bằng matching thật ở T15.

## Chốt thiết kế

- **Retry in-process trong một lần listener invocation** (events.md §4.3 "retry in-process tối đa 3 lần"): attempt đầu + tối đa 3 retry, backoff `app.inbox.retry-backoff-ms` mặc định `1000,3000,10000`; hết lượt → `basicNack(requeue=false)` (broker dead-letter). Không requeue vô hạn.
- **Hai đường DLQ theo events.md §6:** malformed/unsupported = republish chủ động vào `ride.events.dlx` rk `matching.dlq` kèm header `x-dlq-reason` + ACK message gốc (không có `x-death`); transient exhaustion = broker dead-lettering (chỉ `x-death`, không reason). Broker không thể thêm header khi dead-letter, nên malformed KHÔNG dùng reject.
- **Dedup:** unique `(consumer_name, event_id)` trong `inbox_events`; insert + handler chạy trong cùng transaction → row chỉ tồn tại nếu handler commit (§4.2); rollback attempt fail → không có row → xử lý lại từ đầu. consumer-name = `matching-service` (mỗi service một tên riêng — §1/§4.1).
- **Probe table** `matching_probe_events` (unique `event_id`, `ON CONFLICT DO NOTHING`) là side effect quan sát được của handler execution — T14-only, thay bằng logic matching thật ở T15.
- **Topology declare bởi service khi khởi động** qua RabbitAdmin declarables: chỉ exchange + inbox/DLQ + binding của chính mình; không declare trip.inbox/payment.inbox (thuộc service khác).
- **Broker down tolerance:** RabbitAdmin declare lazy trên kết nối đầu tiên; listener container tự retry ở nền; startup không fail khi broker tắt (kiểm chứng spring-rabbit 4.1.1); `health.rabbit.enabled: false` nên readiness = DB only — broker down không làm service DOWN.
- **Fault injection test-only** (`@Primary` bean wrapper probe handler, spec §13 "fault injection chỉ bật bằng profile/env test") — không có knob production.

## Kiểm tra (acceptance spec §20.4)

| Acceptance | Bằng chứng |
|---|---|
| Duplicate thực thi handler đúng một lần | `validEventProcessedOnceAndDuplicateIsIgnored`: republish envelope cùng eventId → inbox row = 1, probe row = 1, `ATTEMPTS` = 1, log `inbox_duplicate`; không có message DLQ |
| Rollback không đánh dấu inbox thành công | `exhaustedRetriesGoToDlqWithoutInboxRow`: 4 attempt đều rollback → không có inbox row; `transientFailureRetriesAndSucceeds`: attempt 1 fail (rollback), attempt 2 commit → đúng 1 row |
| Malformed/unsupported vào DLQ kèm reason, không retry | `malformedAndUnsupportedGoToDlqWithReason`: body không JSON → `x-dlq-reason: malformed_envelope`, raw bytes giữ nguyên; schemaVersion = 2 → `unsupported_schema_version`; cả hai KHÔNG có `x-death` (republish chủ động) |
| eventType consumer không xử lý → DLQ | `unsupportedEventTypeGoesToDlq`: envelope `DriverProposed` gửi thẳng vào queue → `x-dlq-reason: unsupported_event_type`, không inbox row |
| Transient retry bounded rồi thành công | `transientFailureRetriesAndSucceeds`: fail 1 lần, attempt 2 commit — `ATTEMPTS` = 2, đúng 1 log `inbox_retry`, không DLQ |
| Hết retry → DLQ chỉ x-death | `exhaustedRetriesGoToDlqWithoutInboxRow`: đúng 3 log `inbox_retry` + 1 `inbox_dlq/retry_exhausted`; message DLQ có `x-death`, KHÔNG có `x-dlq-reason` |

## Sửa trong lượt (25/10)

- Boot 4 bootstrapper: `@SpringBootTest` cần khai báo explicit `classes = {MatchingServiceApplication.class, FaultInjectionConfig.class}` — annotation trên top-level type KHÔNG thể tham chiếu member type của chính nó bằng simple name (JLS 8.1, xác minh bằng javac repro) → tách `FaultInjectionConfig` thành file top-level test-only cùng package.
- `InboxMessageValidator` là plain class thiếu bean → thêm `@Component`.
- `webEnvironment=NONE` phá security: servlet security auto-config (`ServletWebSecurityAutoConfiguration`, `@ConditionalOnWebApplication(SERVLET)`) không match → không có bean `HttpSecurity` → test chuyển sang MOCK.
- `SecuritySmokeTest` vỡ vì component inbox cần JdbcTemplate (test đã exclude DataSourceAutoConfiguration) → H2 in-memory + tắt Flyway, theo pattern SecurityProbeTest của trip; thêm test dep `h2`.
- PG JDBC bind `byte[]` thành bytea — không cast được `::jsonb` → truyền JSON String ở `insertIfAbsent`/probe handler; listener convert body qua `new String(body, UTF_8)`.
- Test malformed: parse body không-JSON như JSON (bug assert) → so sánh raw bytes.
