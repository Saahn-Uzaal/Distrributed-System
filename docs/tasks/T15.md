# T15 — Matching job thật (matching-service)

Owner: B · Dependency: T09 (DONE), T13 (DONE), T14 (DONE) · Spec §20.4, events.md §2/§3.2/§3.3/§4/§5, api-contracts.md §4.2

## Mục tiêu

matching-service consume `TripRequested` từ queue `matching.inbox`: lưu job/attempt vào `matching_jobs`, gọi candidates API driver-service (internal), bỏ excluded drivers; Matching outbox phát `DriverProposed` (candidates có thứ tự distanceM tăng) hoặc `NoDriverFound`. **Không tự reserve driver** — trip-service nhận proposal và gọi reserve ở T16.

## Chốt thiết kế

- **Gọi HTTP candidates trong transaction mở của listener** (listener bọc inbox-insert + handler.handle trong một TransactionTemplate). Không giữ khóa DB explicit trong lúc gọi HTTP; worst-case giữ connection bị chặn bởi timeout × attempts + backoff. Trade-off ghi nhận — xem lại ở T33 (load test) nếu pool chịu áp lực.
- **Stale-event guard qua chính bảng `matching_jobs`** (`MAX(attempt) > attempt` → skip + ACK, không DLQ): matching không đọc được Trip DB nên đây là cách tự chứa duy nhất để implement events.md §4.4 cho TripRequested; kiểm tra trong transaction cùng ghi job nên race giữa hai event khác attempt an toàn.
- **Job row chỉ ghi ở trạng thái cuối** (PROPOSED/NO_DRIVER_FOUND) trong transaction commit — không có state PENDING cho job; crash trước commit → redelivery chạy lại toàn bộ, dedup theo eventId chống trùng (§4.1).
- **aggregateVersion = 0 lưu DB, bỏ khỏi envelope khi = 0** (field optional §2). Chênh lệch có chủ đích so với publisher trip (luôn ghi field) — matching không biết version trip.
- **Outbox event_type CHECK hẹp** (`DriverProposed|NoDriverFound`) trong bảng outbox của matching (bảng trip chứa đủ 6 type).
- **Fail-fast startup khi thiếu `INTERNAL_API_TOKEN`** qua RequiredDbPasswordValidator (pattern N08/N09) thay vì để các gọi candidates 401 → retry → DLQ.
- **Stub test = JDK `com.sun.net.httpserver.HttpServer`** trên loopback port tự do (không thêm dependency); RestClient đi HTTP thật qua loopback. Stub có `responseJson`, `delayMs`, `timeoutCallsRemaining` (N lần gọi đầu sleep). Test timeout dùng delayMs=900 (> read-timeout client 800 ms, < 800 + backoff đầu 300 ms) vì executor mặc định của JDK HttpServer xử lý request **tuần tự** — call 2 chỉ đến sau khi handler call 1 kết thúc.
- **Test-only declare `trip.inbox` trong test mô phỏng topology T16** (queue durable bind `matching.#`) để outbox publish mandatory=true không bị broker returned; production matching-service vẫn chỉ declare inbox/DLQ/exchange của chính mình (chốt T14 không đổi).

## Giới hạn

- HTTP call trong transaction listener: không giữ khóa DB explicit trong lúc gọi HTTP; worst-case connection hold bị chặn bởi timeout × attempts + backoff. Xem lại ở T33 (load test) nếu pool chịu áp lực.
- Test-only declare `trip.inbox` trong test mô phỏng topology T16 — production matching-service vẫn chỉ declare inbox/DLQ/exchange của chính mình (chốt T14).
- Không chạy migration vào DB dev (`matching_db`) — kiểm chứng bằng Testcontainers only.

## Sửa trong lượt (25/10)

- **Bug quan trọng**: test-scoped `@Configuration` cùng package với app bị component-scan khi chạy test (surefire đặt target/test-classes lên classpath; scan theo tên package). `FaultInjectionConfig` cũ ở `com.ridehailing.matching` làm probe handler `@Primary` của nó thắng injection trong MỌI test context, thay MatchingJobHandler một cách im lặng (triệu chứng: inbox row commit nhưng không có job/outbox row, zero log handler). Sửa = chuyển sang package `com.ridehailing.matchingtest` + đăng ký explicit `classes={...}` ở test T14. Bài học cho task sau: mọi @Configuration chỉ-dùng-test phải nằm ngoài cây package của app.
- MatchingJobHandler compile fixes: interface `InboxEventHandler.handle` không khai báo checked throws → bỏ `throws Exception`, bọc `serialize()` try/catch(Exception)→IllegalStateException; sửa type-inference Map.of bằng lambda LinkedHashMap explicit.
- OutboxPublishWorker effectively-final fix (helper `publishSafely`).
- Phát hiện API test: JDK 21 `HttpExchange` KHÔNG có `sendResponseBody` — dùng `getResponseBody().write(...)` sau `sendResponseHeaders(code, len)`; spring-rabbit 4.x `RabbitTemplate` không có `purgeQueue` → raw channel `queuePurge` (amqp-client 5 đổi tên); persistence message nhận assert qua `getReceivedDeliveryMode()` (spring-amqp 4.x — `getDeliveryMode()` null cho message received); JDK 21 `HttpServer.create` chỉ overload `(addr, backlog)`, không có ExecutorService.
