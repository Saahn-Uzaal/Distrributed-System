# T16 — Trip nhận proposal và reserve (trip-service)

Owner: A · Dependency: T11 (DONE), T12 (DONE), T13 (DONE), T14 (DONE), T15 (DONE) · Spec §20.4, events.md §1/§2/§3.2/§3.3/§4/§5/§6, state-machines.md §1/§2, api-contracts.md §4.1/§4.2

## Mục tiêu

trip-service consume `DriverProposed`/`NoDriverFound` từ queue `trip.inbox`: thử reserve candidate theo thứ tự qua internal API driver-service (`PUT /internal/reservations/{id}`), lưu `reservationId` rồi cập nhật trip sang `DRIVER_OFFERED`; hết candidate hoặc `NoDriverFound` → retry attempt+1 (outbox `TripRequested`) hoặc terminal `NO_DRIVER`. Proposal stale bị bỏ qua có log; reserve conflict thử candidate kế tiếp; timeout đọc lại cùng reservation bằng GET; không giữ DB lock khi gọi HTTP.

## Chốt thiết kế

- **Stale-event guard (§4.4)**: trip phải ở `SEARCHING` với `matching_attempt == attempt`, ngược lại → log `stale_event_skipped` + ACK (event hợp lệ nhưng cũ — không vào DLQ). Kiểm tra trong transaction cùng dedup insert nên race giữa hai event khác attempt an toàn.
- **Không giữ DB lock khi gọi HTTP**: mọi đọc trước, HTTP ở giữa, mọi ghi sau — trong transaction duy nhất của listener; CAS `version+phase` (saga) và `(state, matching_attempt)` (trips) serialize intent; 0 rows → RuntimeException → rollback + retry bounded.
- **Idempotent theo eventId**: reservationId/commandId deterministic UUID v3 (`RESERVE|tripId|attempt|index`, `CMD-RESERVE|...`) — redelivery sau crash replay idempotent phía driver (§4.1: cùng commandId+hash → replay 201). Replay với expiresAt mới → hash khác → 409 `COMMAND_CONFLICT` → reconcile bằng GET trên CÙNG reservationId; state RESERVED khớp trip/driver/attempt = thành công.
- **Timeout HTTP không suy ra thất bại**: đọc lại cùng reservationId (GET); 200 RESERVED khớp → success; 404/mismatch → retry PUT MỘT lần với commandId cũ + expiresAt mới (§4.1: commandId ổn định khi retry); vẫn mù → RuntimeException (listener retry bounded chạy lại toàn flow — deterministic id giữ an toàn).
- **Exhaustion rule**: `attempt >= MAX_MATCHING_ATTEMPTS || now > saga.deadline_at` → NO_DRIVER terminal (trips CAS, trip_event `NO_DRIVER` version = trips.version mới, saga ABORTED, không phát event mới); ngược lại SEARCHING→SEARCHING attempt+1: bumpMatchingAttempt + saga `next_retry_at = now + MATCHING_RETRY_DELAY_MS` + outbox PENDING `TripRequested` payload `{tripId, attempt:n+1, pickup, excludedDriverIds}` với **causationId = envelope.eventId()** (§5), aggregateVersion = trips.version mới.
- **excludedDriverIds KHÔNG cập nhật ở T16** (giữ nguyên từ saga context) — cập nhật danh sách loại thuộc T19 (reject và tìm lại).
- **Success path writes (cùng transaction)**: saga CAS → `WAITING_DRIVER` context `{reservationId, driverId, driverUserId, attempt}`; trips CAS markDriverOffered; trip_event `DRIVER_OFFERED`. Ghi `trips.driver_id`/`driver_user_id` khi DRIVER_OFFERED theo chốt N22 — assignment hiệu lực chỉ từ ACCEPTED (T18).
- **Fail-fast startup khi thiếu `INTERNAL_API_TOKEN`** qua RequiredDbPasswordValidator (pattern N08/N09) thay vì để các gọi reserve 401 → retry → DLQ.

| Acceptance | Bằng chứng |

| Reserve conflict thử candidate tiếp theo | `reserveConflictTriesNextCandidate`: stub trả 409 `DRIVER_NOT_AVAILABLE` cho A → handler thử B; B thắng → trips.driver_id = B, thứ tự call A→B |

| Không giữ DB lock khi gọi HTTP | Kiến trúc handler: đọc trước / HTTP giữa / ghi sau trong 1 transaction listener (mục "Chốt thiết kế"); mọi test integration chạy trên PG thật không phát hiện deadlock/lock-wait trong log |
| Hết candidate chưa exhausted → retry attempt+1 | `exhaustedCandidatesRetriesNextAttempt`: mọi candidate conflict, attempt < max → SEARCHING→SEARCHING attempt+1 + outbox PENDING TripRequested causationId = eventId DriverProposed (§5) |

## Giới hạn

- HTTP call trong transaction mở của listener: không giữ khóa DB explicit trong lúc gọi HTTP; worst-case connection hold bị chặn bởi timeout × attempts + backoff. Xem lại ở T33 (load test) nếu pool chịu áp lực.
- `excludedDriverIds` không cập nhật ở T16 — thuộc phạm vi T19.
- Payment event (`payment.#`) tới trip.inbox trước T24 → DLQ với `x-dlq-reason: unsupported_event_type` (đúng contract §2, không cần xử lý đặc biệt).
- Không chạy migration vào DB dev (`trip_db`) — kiểm chứng bằng Testcontainers only.

## Sửa trong lượt (25/10)

- **Bug runtime 1**: `SagaRepository.findByTripId` cast cột jsonb `context` qua `(String) rs.getObject(...)` → `ClassCastException: PGobject cannot be cast to String` trên mọi attempt handler (triệu chứng: inbox_retry ×3 → DLQ, không có row nghiệp vụ). Sửa: `rs.getString("context")`.
- **Bug runtime 2**: Spring Framework 7 `RestClient` ném **`RestClientException`** ("Error while extracting response...") khi read-timeout — KHÔNG phải chỉ `ResourceAccessException` → catch cũ bỏ sót, listener retry bằng PUT thứ hai thay vì GET reconcile (triệu chứng: stub ghi `[PUT, PUT]`). Sửa: broaden `catch (RestClientException)` ở cả 2 nhánh timeout + comment giải thích.
- **Assertion stale**: `TripIntegrationTest.v2UpgradePreservesOriginalOwnerReplayAndEnforcesCompleteAssignmentIdentity` assert Flyway current version `"5"` — cũ sau khi V6 (`sagas`+`inbox_events`) tồn tại; cập nhật thành `"6"`.
- API Spring Framework 7: `RestClientResponseException.getResponseBody()` không tồn tại → dùng `getResponseBodyAsByteArray()` (verify bằng javap trên jar m2 local) trong `DriverReservationClient.parseErrorCode`.
