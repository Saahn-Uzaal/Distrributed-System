## Bằng chứng kiểm tra (lệnh thật)
1. **Declare topology**: `bash infra/rabbitmq/declare-topology.sh` → `T04: topology declared over AMQP (host=rabbitmq).` (one-off container trên `ridehailing_net`, kết nối AMQP qua DNS `rabbitmq`).
2. **Durable flags** — management API (`127.0.0.1:15672`):
   - `GET /api/exchanges/%2F`: `ride.events` + `ride.events.dlx`, cả hai `"type":"topic","durable":true`.
   - `GET /api/queues/%2F`: đủ 6 queue, tất cả `"durable":true`.
3. **Bindings**:
   - `GET /api/queues/%2F/{matching|trip|payment}.inbox/bindings` → mỗi inbox có binding từ `ride.events` với routing key đúng (`trip.requested`, `matching.#`, `trip.completed`) + binding default-exchange ngầm.
   - `GET /api/queues/%2F/{matching|trip|payment}.dlq/bindings` → mỗi DLQ bind vào `ride.events.dlx` với `routing_key` = tên queue. (Endpoint exchange-side trả body rỗng ở bản API này — xác minh qua phía queue.)
4. **DNS trong network**: one-off container trên `ridehailing_net`: `getent hosts rabbitmq postgres` → `172.20.0.3 rabbitmq`, `172.20.0.2 postgres`.
5. **Publish/consume qua mạng, message persistent**:
   - `POST /api/exchanges/%2F/ride.events/publish` (routing_key `trip.requested`, `delivery_mode:2`, envelope chuẩn mục 9) → `{"routed":true}` HTTP 200.
   - `POST /api/queues/%2F/matching.inbox/get` body `{"ackmode":"ack_requeue_false","count":"1","encoding":"auto"}` → payload envelope nguyên vẹn (455 bytes), `"delivery_mode":2`, exchange `ride.events`.
6. **DLQ proof**: publish msg thứ 2 vào `matching.inbox` → get với `ackmode:"reject_requeue_false"` (nack, không requeue) → `matching.dlq` messages:1; payload có header `x-death` (`reason:"rejected"`, exchange `ride.events`, queue `matching.inbox`). Ack dọn sạch sau đó.
7. **Persistence qua restart broker**: publish persistent msg routing key `matching.proposed` → `trip.inbox` messages:1 → `docker stop ridehailing-rabbitmq && docker start ...` → healthy (~8s) → count vẫn 1, consume payload nguyên vẹn (452 bytes).
