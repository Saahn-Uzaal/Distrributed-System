# T09 — Driver profile và vị trí (DONE, 2026-10-20)

Phạm vi theo spec §20.4 (owner B): driver/vehicle migrations; profile, availability, location, heartbeat; internal candidates API lọc heartbeat + khoảng cách. **Chưa** reserve/matching orchestration (T10+). Nguồn sự thật: `docs/api-contracts.md` §3.2/§4.2, `docs/state-machines.md` §4.

## Quyết định chốt trong task (đã ghi vào contract)
- Thêm mã lỗi **409 `PLATE_TAKEN`** (§1.2) — plate trùng trong driver_db; rollback transaction nên không có driver row cho user thứ hai.
- User chưa có profile gọi availability/location → **404 `NOT_FOUND`**.
- PUT availability khi đang `RESERVED`/`BUSY` → **409 `STATE_CONFLICT`** với **mọi** status yêu cầu (state machine §4 không có transition PUT từ RESERVED/BUSY); details = `{state, tripId}`.
- Candidates: `limit` default 5, `<1` → 400, `>5` clamp về 5; `radiusM` bắt buộc > 0; chỉ driver `AVAILABLE` + heartbeat mới (`HEARTBEAT_STALE_AFTER_MS=15000`) + có tọa độ; sắp deterministic `distanceM` tăng → tie-break `driverId` lexicographic.
- Hai bảng riêng `vehicles` + `drivers` (đúng nghĩa "Driver/vehicle migrations"); `drivers.current_reservation_id`/`current_trip_id` khai báo sẵn — T10/T18 set, T09 chỉ đọc trong details STATE_CONFLICT.
- Plain JDBC (`JdbcTemplate`) + Flyway, không JPA ở driver-service (nhất quán baseline T03).
- PUT availability cũng cập nhật heartbeat `last_seen_at`. Haversine R = 6.371.008.8 m; distanceM làm tròn xuống long meters; candidates tính trong Java (fetch AVAILABLE + fresh, lọc radius, sort).

## Lỗi gặp và đã sửa trong lượt này (bằng chứng chạy thật)
1. **Compile error javac** `inference variable T has incompatible bounds` ở mọi `jdbc.query(sql, args, this::mapX)`: Spring Framework 7 thêm overload `<T> T query(String, Object[], ResultSetExtractor<T>)`; method reference 1-arg `(ResultSet)` chỉ khớp `ResultSetExtractor` (trả `T`, không `List<T>`) → inference conflict. **Sửa**: mapper methods đổi signature thành `(ResultSet, int)` đúng contract `RowMapper.mapRow`. Verify bằng repro javac standalone trên jar spring-jdbc 7.0.9 trước khi sửa file thật.
2. **Compile errors test**: `new JWSObject(payload)` không tồn tại → `new JWSObject(new JWSHeader(RS256), payload)` + `jws.sign(SIGNER)`; `jdbc.update(... RETURNING id)` trả int → `queryForObject` với RowMapper lambda 2-arg + helper `toUuid` (pgjdbc có thể trả UUID hoặc String cho cột uuid).
3. **Runtime 500** ở PUT availability: `BadSqlGrammarException` — thứ tự args trong `updateAvailabilityIfFree` sai (`status` nhận Timestamp, `updated_at` nhận String) → PG: `column "updated_at" is of type timestamp with time zone but expression is of type character varying`. Phát hiện bằng repro pgjdbc standalone trên postgres thật (psql literal không bắt được vì binding JDBC khác). **Sửa**: thứ tự `(newStatus, ts, ts, driverId)`.
4. **SecurityProbeTest context fail** (`No qualifying bean of type JdbcTemplate`): test exclude DataSourceAutoConfiguration nhưng T09 thêm bean phụ thuộc JdbcTemplate. **Sửa**: H2 in-memory `jdbc:h2:mem:driver_probe;DB_CLOSE_DELAY=-1`, flyway tắt — probe không chạm DB, không cần Docker/Postgres dev.
