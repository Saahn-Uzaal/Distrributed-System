## Mục tiêu

Worker saga bền vững ở trip-service xử lý 4 việc pending mà request path không tự hoàn tất:

1. **Offer timeout** — trip vẫn `DRIVER_OFFERED`, offer TTL (`offerExpiresAt`) hết hạn mà không ai accept/reject → release reason `OFFER_EXPIRED` → tìm lại (SEARCHING attempt+1, excluded += driver) hoặc NO_DRIVER ở lượt cuối.
2. **Deadline tổng tìm tài xế** — saga `WAITING_MATCH` quá `deadline_at` (`TRIP_MATCH_DEADLINE_SECONDS`, mặc định 120 s) mà matching im lặng/crash → release MỌI reservationId tất định của attempt hiện tại (tombstone cho reserve đang bay, F06/N24) → NO_DRIVER + saga ABORTED.
3. **Intent treo** — `CONFIRMING` (accept timeout/chết giữa chừng) hoặc `COMPENSATING` (reject/cancel release chưa rõ) → resume idempotent bằng đúng các hàm reconcile của request path.
4. **Restart** — tiến trình mới đọc DB và tiếp tục mọi việc pending trên (lease + CAS đảm bảo không chạy trùng).

Acceptance spec §20.5: "Restart Trip ở RESERVING/COMPENSATING tiếp tục đúng; late reserve không hồi sinh tombstone; CONFIRMED không bị giải phóng do offer TTL."

## Chốt thiết kế

- **Lease:** claim = transaction ngắn {`FOR UPDATE` + re-check phase/version + CAS version + ghi `lease_owner` + re-arm `next_retry_at = now + lease`}. Điều kiện due **không** yêu cầu `lease_owner IS NULL`: worker chết giữa chừng để lại lease cũ, sau khi `next_retry_at` hết hạn saga được claim lại và intent replay idempotent (commandId tất định + CAS). Lease cũ vô hại; xóa khi xong cho hygiene.
- **CONFIRMING/COMPENSATING luôn actionable** khi `next_retry_at IS NULL OR <= now`: intent treo theo định nghĩa là việc pending; re-arm lúc claim tạo backoff (mặc định 5 s) thay vì hammer driver-service.
- **Song song an toàn:** request handler + worker double-confirm cùng trip → cùng commandId tất định → driver dedup (§4.1); mọi completion serialize trên khóa row saga và idempotent. Race user-reject vs worker-expiry hội tụ về cùng trạng thái terminal.
- **Deadline cleanup (F06/N24):** release MỌI `maxCandidates` reservationId tất định của attempt hiện tại TRƯỚC khi đánh NO_DRIVER — reserve tới trễ nhận 409 `TOMBSTONED_RESERVATION`, không hồi sinh ("late reserve không hồi sinh tombstone"). Reason dùng: `CANCELLED` (cùng T20 cancel-from-SEARCHING).
- **Event worker-driven:** rematch sau timeout nội bộ phát `TripRequested` với correlationId mới (`UUID.randomUUID()`), causationId null — timeout nội bộ không có event upstream (events.md §5).
- **offerExpiresAt:** một giá trị duy nhất mỗi lượt handler → request hash ổn định khi retry; lưu "giá trị gửi trong lượt này" an toàn dù driver giữ expires_at cũ từ PUT trước. Worker so theo đồng hồ DB (`clock_timestamp()`, R04).
- **CONFIRMED không bị offer TTL giải phóng (invariant 8):** phía driver chỉ cho release CONFIRMED với reason `CANCELLED` (enforce cả hai phía) → đường `OFFER_EXPIRED` của worker không thể đụng assignment đã confirm; kết quả `REFUSED` → log-only, không đổi saga. Release reservation đã terminal trả 200 + trạng thái terminal (idempotent).
- **Phase RESERVING_DRIVER** tồn tại trong schema/contract nhưng T16 implement WAITING_MATCH→WAITING_DRIVER trực tiếp — không có code nào set phase này; "restart ở RESERVING" được cover bằng test restart ở các phase thực sự xảy ra: WAITING_MATCH / WAITING_DRIVER / CONFIRMING / COMPENSATING.
- **Deterministic test:** trong mọi test dựa trên `TripCommandTestSupport`, tắt worker schedule (`worker-interval-ms=3600000`) — tick 1 s có thể claim intent treo giữa commit intent và HTTP call, tiêu thụ fault flag (stub sleep 1500 ms rồi 503) trước request. Hành vi worker được test tường minh qua `processDueSagas()` ở cả hai test mới (cùng code path với tick production); restart test dùng context interval dài + gọi tường minh để không có race với assertion.
