## Quyết định chốt T12 (ghi vào code comment + tài liệu)

1. **Outbox schema tạo ở T12** (không phải T13): spec nói T12 "ghi ý định yêu cầu matching trong DB/**outbox pending**" — nên bảng `outbox` phải tồn tại và row PENDING `TripRequested` attempt 1 được insert **cùng transaction** với trip. T13 chỉ thêm publisher worker (scan pending → publish confirms → đánh dấu SENT).
2. **Saga row `WAITING_MATCH` chưa ghi ở T12**: schema `sagas` thuộc T16 — không code sẵn task sau.
3. **Notification passenger chưa ghi ở T12**: bảng/endpoint notifications thuộc T25 ("Notifications và trip event history").
4. **`trip_events` tạo ở T12** (thuộc "Trip migration") + row `TRIP_CREATED` version 1 ghi tại transition đầu – → SEARCHING (contract §3.5: "ghi tại mỗi transition"; endpoint GET events thuộc T25).
5. **Idempotency claim bằng `INSERT ... ON CONFLICT (key) DO NOTHING`** trong transaction: hai request cạnh tranh cùng key chỉ một bên claim; bên kia đọc row đã lưu → replay hoặc 409 — không cần xử lý exception unique, toàn bộ atomic.
6. **`request_hash` = SHA-256 hex của payload canonical** `destLat|destLng|pickupLat|pickupLng` (chỉ tọa độ — fare tính server-side nên không nằm trong hash). Pattern "chốt T10" áp dụng lại.
7. **`stored_response` JSONB = `{"status":<int>,"body":{...}}`** — replay trả đúng status/body gốc (202 + body trip). Header `Location` tái sinh từ `tripId` trong body replay.
8. **Fare server-side**: `distanceM = round(haversine)` (R = 6_371_008.8 m, class `Haversine` nhân bản từ driver-service T09); `fareVnd = FARE_BASE_VND + ceil(distanceM/1000) * FARE_PER_KM_VND`, env `FARE_BASE_VND=12000`, `FARE_PER_KM_VND=5000` (mới trong `application.yml` + `.env.example`).
9. **GET /api/trips sort**: contract không chốt thứ tự list → chọn `created_at DESC, id` (deterministic, ổn cho phân trang). Ghi ở đây để task sau tham chiếu.
