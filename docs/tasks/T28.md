## Chốt thiết kế (chưa được user phê duyệt — người thực hiện tự quyết)

- **Trang đơn `/driver`** (không sub-route).
- **Boot probe**: khi mount, `PUT /api/drivers/me/availability` với status cache từ sessionStorage (mặc định AVAILABLE nếu chưa có cache; cache stale RESERVED/BUSY → probe AVAILABLE, server 409 làm rõ state thật); 200 → tin response; 409 STATE_CONFLICT `{state, tripId}` → khôi phục busy state + link chuyến; 404 NOT_FOUND → form tạo hồ sơ.
- **Hiển thị profile**: re-POST idempotent (server bỏ qua body khi profile đã tồn tại — verified trong `DriverService.createProfile`); cache displayName/plate/vehicleType vào sessionStorage làm payload cho lần gọi sau.
- **Heartbeat**: PUT location mỗi 10 s chỉ khi AVAILABLE (matching cần `last_seen_at < 15 s`); cleanup khi unmount/offline/busy.
- **Poll offer**: mỗi 3 s khi AVAILABLE/RESERVED; đếm ngược theo `expiresAt`; nút accept disable khi offer hết hạn.
- **Accept reconcile**: POST accept `{attempt}` → nếu 202 DRIVER_OFFERED (confirm chưa rõ) thì poll trip tới ACCEPTED — không bao giờ hiện "đã nhận" trước khi server nói ACCEPTED (§T18).
- **Recovery sau trip terminal**: BusyTripPanel probe `PUT availability('AVAILABLE')` mỗi 5 s tới khi server giải phóng driver (finish T22) → về AVAILABLE.
- **Disable theo state** ("disable thao tác sai trạng thái"): accept khi hết hạn, start ≠ ACCEPTED, complete ≠ IN_PROGRESS, online/offline khi RESERVED/BUSY.
