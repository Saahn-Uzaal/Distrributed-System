## Mục tiêu

Assigned driver bắt đầu và kết thúc chuyến:

- **Start** — state phải là `ACCEPTED`, chỉ assigned driver → `IN_PROGRESS` + trip_event `TRIP_STARTED`.
- **Complete** — state phải là `IN_PROGRESS`, chỉ assigned driver → `COMPLETED` + `payment_status=PENDING`, `payment_attempt=1` + trip_event `TRIP_COMPLETED` + outbox `TripCompleted` (attempt 1, `amountVnd = fare_vnd`, currency VND) + **intent finish bền** (saga `AWAITING_FINISH` + desired `FINISH_ASSIGNMENT`).
- **Finish driver** — sau complete gọi finish của driver-service (commandVersion 4); thành công → saga `COMPLETED` terminal; chưa rõ → intent giữ trong saga, worker resume.

Acceptance spec §20.5: "Chỉ assigned driver start/complete; complete lặp không phát intent nghiệp vụ mới; finish retry giải phóng đúng driver."

## Chốt thiết kế

- **Complete flow:** Tx1 commit trip COMPLETED + outbox TripCompleted **TRƯỚC** khi gọi finish — response luôn 200 bất kể kết quả finish; finish là intent saga bền, không nằm trong kết quả HTTP (spec §10 rule 6: "Complete ghi Trip COMPLETED, intent release driver và TripCompleted qua outbox. Worker finish assignment idempotent.").
- **Complete lặp trên COMPLETED → 409 STATE_CONFLICT** — guard chạy trước mọi ghi: không có row outbox mới, `payment_attempt` không đổi (acceptance "complete lặp không phát intent nghiệp vụ mới").
- **Start lặp trên IN_PROGRESS → 409 STATE_CONFLICT** (contract §3.3: state phải là ACCEPTED).
- **Finish reconcile:** GET `RELEASED` + khớp tripId = đã xong — an toàn vì sau CONFIRMED đường terminal duy nhất là finish TRIP_COMPLETED (release của CONFIRMED chỉ chấp nhận CANCELLED, cancel sau ACCEPTED trả 409 ở trip-service; CONFIRMED không bao giờ expire).
- **commandVersion finish = 4** (dòng "Chốt T18–T20" contract §4.1: reserve=1, confirm=2, release=3, finish=4 ở T22).
- **TripCompleted:** correlationId = X-Correlation-ID của request complete (nhất quán với reject T19); causationId NULL — event HTTP-triggered (events.md §5); payload `{tripId, attempt:1, amountVnd=fare_vnd, currency:"VND"}`; routing key `trip.completed` (§3.4).
- **Worker resume:** cùng code path với request (`finishWithReconcile` + `completeFinish`); commandId tất định theo reservation → replay idempotent phía driver (dedup §4.1); khóa row saga serialize với request song song; `resumePendingFinish` chỉ hành động khi phase AWAITING_FINISH + desired FINISH_ASSIGNMENT, khác thì no-op.
- **Không cần migration mới:** outbox.event_type CHECK đã gồm 'TripCompleted' (V2), trip_events.type CHECK đã gồm TRIP_STARTED/TRIP_COMPLETED (V2), `trips.payment_status`/`payment_attempt` tồn tại từ V2.
